# 领域约定

运河纠纷程序衔接引擎围绕海事争议、程序移送与期限保存可核对的业务记录。外部主体使用不含真实身份信息的稳定引用编号，时间采用带偏移量的 ISO 8601 字符串，材料只保存受控引用和 `sha256` 摘要。

## 对象模型

- **当事方（parties）**：只登记最小身份资料——`party_ref`、主体类型、身份散列 `id_hash` 与联系方式引用。身份散列仅用于重复立案识别，不反推真实身份。
- **案件（cases）**：登记争议类型（水上交通事故、船员劳资、船舶污染、货物运输）、管辖连接点、当事人程序选择、仲裁协议与涉外标记、保密级别（L1/L2/L3 依次升高）。
- **请求事项（claims）**：一个案件可含多项请求。重复立案识别以请求为粒度：同当事人、同争议类型、同请求类型才标记疑似重复，且只标记、由人工确认或排除；请求类型不同属于不同请求，绝不合并。
- **证据封存（evidence_seals）**：只保存 `sha256` 摘要、封存单位与时间，不保存材料内容。
- **法定期限（deadlines）**：登记依据条文、起止与预警天数。移送不中止法定时效，引擎只计算剩余天数并在移送快照与监督视图中预警。
- **程序路径（path_versions / path_nodes）**：受理后按争议类型与当事人选择生成，每个节点都附规则理由（可解释）。撤回、部分和解、管辖异议、跨境送达均另起版本，旧版本只标记更替时间，永不删除。
- **移送（transfers）**：每次移送先由交出单位确认、再由接收单位确认，顺序不可逆；材料清单、保密级别与期限快照随移送保存。交接完成后接收单位获得授权，案件保密级别就高调整。
- **授权（grants）**：协同单位按案件获得范围（进度、材料）与具体证据引用，未授权单位不可见。
- **事件（events）**：包含 `event_id`、`subject_ref`、`occurred_at`、`source_sequence` 和 `payload_digest`。来源序号只在同一来源内递增，接收方必须保留原始发生时间，不得用到达时间覆盖；`event_id` 幂等，重复投递返回首次记录。

## 角色与可见性

- **公众（public）**：只能查看本人案件的进度视图，不含证据摘要与他人信息。
- **协同单位（unit）**：查看获授权案件的授权材料；仅当前责任单位可发起移送。
- **登记（registrar）**：登记当事方与案件、受理生成路径、裁决重复立案标记。
- **监督（supervisor）**：按任一节点核对实际停留时间、效力状态与下一责任方，可见全部版本与移送记录。

示例内容仅用于说明字段形状，不代表真实人员、机构或业务结论。
