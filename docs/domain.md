# 领域约定

运河纠纷程序衔接引擎围绕**水上事故、船员劳资、船舶污染、货物运输**四类争议，保存可核对的业务记录，
支撑海事、检察、司法行政、人社、调解、劳动仲裁、商事仲裁、法院八家共建单位之间的
一口受理、程序衔接与双向交接。

## 标识与脱敏

- 所有主体使用不含真实身份信息的稳定引用号：案件 `CASE-YYYY-NNNNN`、移送 `TRF-...`、
  当事方 `PARTY-...`、证据 `EVD-...`、事件 `EVENT-<案号>-NNNN`。
- 最小身份资料只保存引用与角色（claimant/respondent/third_party）、联系方式引用；
  证件号、电话号码等不进引擎。
- 材料只保存受控引用与 `sha256:<hex>` 摘要（证据封存、移送材料包、域外回证同理），
  原件由持有人单位保管；移送时接收方必须先比对摘要，不一致即拒签退回。
- 时间一律采用带偏移量的 ISO 8601（东八区）。外部事件保留 `occurred_at` 原始发生时间，
  另存 `received_at`，到达时间永远不得覆盖发生时间；`source_sequence` 只在同一来源内递增。

## 核心对象

- **cases**：案件主记录（争议类型、法律关系引用 `relation_ref`、受理时间、时效口径）。
- **parties / claims / connections / evidence**：当事方、请求事项、管辖连接点、证据封存摘要。
- **routes / stages**：程序路径是**版本化**的。首版由争议类型与当事人选择生成；
  管辖异议成立、插入跨境送达等改道一律新增版本，旧版本置 `superseded`/`void` 但只读保留，
  不删除、不覆盖。每个节点标注责任单位、法律依据、选择理由、办理期限与交接出口。
- **transfers**：跨单位推进必须发起移送，状态机
  `proposed → received`（签收，交接完成）或 `proposed → rejected`（拒收，退回补正），
  交出与接收双方留痕；未完成双向确认前责任不转移。
- **tolls**：期限中止区间。移送等待签收、管辖异议审查、跨境送达等待域外回证期间，
  法定时效/起诉期间**中止不计入**；恢复后已用天数与剩余额度保持不变。所有中止/恢复均留痕。
- **events**：案内只追加事件账本，案内序号严格递增。
- **grants**：单位对案件的授权（progress/materials）与保密级别上限
  （public < restricted < confidential < secret）；材料授权在正式签收时按节点落地，
  超级别字段对未获授权单位屏蔽。

## 重复立案的两级指纹

- 强指纹 = 当事方集合 + 争议类型 + 法律关系引用 + 请求事项集合（顺序无关）。
  命中在办案件即**拦截重复立案**（全部撤回后可重新立案，也可带 `force` 强制提交）。
- 弱指纹 = 当事方集合 + 争议类型。命中但请求不同时**只建立关联、绝不自动合并**：
  例如同一航次的工资请求与人身损害赔偿是两个并行案件。

## 状态语义

- 案件：accepted / partial_settled / withdrawn / closed。
  部分和解只变更被和解请求的状态，其余请求沿原路径继续，禁止全案合并结案；
  全部撤回使当前路径失效（void）但留痕。
- 节点：pending / active / handed_off / superseded / closed / void。
- 监督口径下，每个活动节点都能核对：实际停留时间、办理期限是否超期、
  当前责任方、下一责任方与案件效力状态。

> 文中出现的法律期限与依据仅用于程序解释与预警口径，具体个案以有权机关认定为准。
